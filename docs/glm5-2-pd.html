GLM5.2 / P3D4 / Long Context

GLM5.2 PD 部署操作手册

公开展示版。该手册面向 GLM5.2 FP8 多节点推理部署，展示从拓扑规划、容器启动、通用环境变量、P/D 角色脚本到流式问答验证的完整交付链路。内部环境信息已脱敏。

P3D4Prefill / Decode 拓扑 256K长上下文配置 FP8推理优化 Stream流式问答验证

1. 部署拓扑

Prefill x 3三节点承担长上下文 Prefill，支持上下文并行与流水分层。
Decode x 4四节点承担 Decode，支持持续生成和并发请求。
Router统一入口，负责请求转发、worker 等待和 OpenAI 兼容接口。
Logs按运行批次输出拓扑、角色日志、指标与验证结果。

2. 交付内容

  • 容器启动方案：统一镜像、MUSA 能力、共享目录、容器内 SSH 和目标节点检查。
  • 公共环境脚本：集中管理通信、MUSA、SGLang、DeepEP、上下文长度和缓存相关变量。
  • Prefill 脚本：配置 TP/EP/PP、长上下文、chunked prefill、指标导出和 P/D 通信。
  • Decode 脚本：配置 DP attention、EAGLE 推测解码、显存比例和 Decode 角色端口。
  • Router 脚本：启用 PD disaggregation，配置 worker 等待、超时、调度策略和统一端口。
  • 验证脚本：用流式问答确认 token 持续输出，并统计首 token 延迟、总耗时和 chunk 数。

3. 运行顺序

01

读取 hostfile，确认 Prefill 和 Decode 节点数量满足拓扑要求。

02

检查目标容器是否存在且运行，避免在错误环境下拉起服务。

03

按 rank 启动 Prefill 节点，生成独立日志。

04

按 rank 启动 Decode 节点，继承统一上下文和推测解码配置。

05

在入口节点启动 Router，并通过健康检查和流式问答验收。

4. 技术亮点

长上下文工程化

围绕 64K/128K/256K 上下文配置，梳理 Prefill、Decode 和 Router 的一致性参数。

脚本化拓扑

将 P3D4 拓扑、rank、日志目录和模型路径参数化，减少现场手工配置。

流式验证

用标准 chat completions 流式请求验证端到端链路，而不是只看端口存活。

排障闭环

沉淀日志位置、停服脚本和残留进程检查，便于客户交接后独立运维。

5. 验收标准

  • Prefill、Decode、Router 三类服务均能按拓扑启动。
  • 健康检查正常，模型接口可访问。
  • 流式问答持续输出 token，并正常结束。
  • 日志目录可追踪每个角色的启动与运行状态。
