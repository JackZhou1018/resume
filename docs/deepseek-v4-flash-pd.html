SGLang / MUSA / PD Disaggregation

DeepSeek V4 Flash PD 分离部署手册

公开展示版。该手册来自真实客户交付场景，重点展示多节点推理服务拆分、自动化脚本封装、日志与接口验证流程。内部地址、路径、端口、密钥和完整脚本已做脱敏处理。

3P1DPrefill / Decode 拆分 RouterOpenAI 兼容入口 FP8模型推理部署 Runbook客户可执行手册

1. 部署架构

Prefill Group多节点负责长上下文 Prefill 计算
Decode Node独立 Decode 节点负责持续生成
Router统一暴露 OpenAI 兼容接口

架构采用 P/D 分离：Prefill 侧负责大块上下文计算，Decode 侧负责 token 生成，Router 侧屏蔽后端拓扑，对客户提供稳定访问入口。

2. 交付内容

  • 容器创建脚本：统一镜像、GPU/MUSA 能力、共享存储挂载与容器间通信准备。
  • 一键拉起脚本：按顺序启动 Prefill、Decode 和 Router，降低客户误操作概率。
  • 停止脚本：精确清理推理服务相关进程，避免影响其他系统服务。
  • 日志规范：按角色拆分 Prefill、Decode、Router 日志，方便定位启动失败、端口占用和 worker 等待问题。
  • 验证命令：提供模型列表、简单问答、OpenAI 兼容接口调用与服务健康检查。

3. 标准操作流程

01

确认模型、镜像、共享存储和节点连通性。

02

创建或刷新推理容器，完成容器间免密和基础环境初始化。

03

先清理旧服务，再执行一键拉起脚本提交 PD/R 服务。

04

跟踪各角色日志，确认 worker、Router 和接口全部就绪。

05

用模型列表和 chat completions 请求验证业务链路。

4. 技术亮点

分离式推理

将 Prefill 与 Decode 角色显式拆分，提升长上下文请求下的资源调度清晰度。

客户可执行

把复杂部署动作收敛成容器创建、启动、验证、停止四类命令，降低交接成本。

可观测性

通过角色日志和接口验证命令建立标准排障路径，便于现场快速定位。

安全边界

停服脚本只匹配推理相关进程，避免误杀 DCGM、监控或其他业务服务。

5. 验收标准

  • Router 健康检查正常，模型列表接口可返回目标模型。
  • 简单问答请求可稳定返回内容。
  • Prefill、Decode、Router 日志均无阻断性错误。
  • 停服脚本执行后无残留推理服务进程。
